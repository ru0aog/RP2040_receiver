# 🛰️ Pico-SDR SSB/RTTY Receiver (RP2040)  
  
[![Platform: RP2040](https://shields.io)](https://raspberrypi.com)  
[![Framework: Arduino-Pico](https://shields.io)](https://github.com/earlephilhower/arduino-pico)  
[![License: AGPL--3.0](https://shields.io)](LICENSE)  
  
Программно-определяемый радиоприёмник (**SDR**) прямой оцифровки на **Raspberry Pi Pico (RP2040)**.  
Реализует полный тракт DSP: квадратурный захват встроенным ADC, комплексный DDC  
(NCO-сдвиг + CIC + half-band фильтры), демодуляцию **SSB** (USB/LSB) через  
преобразование Гильберта, НЧ-фильтрацию рабочей полосы `0…3 кГц`, ресемплинг  
в `44.1 кГц` и потоковый вывод **USB Audio** на ПК. Дополнительно есть бортовой  
декодер **RTTY** и CAT-управление по протоколу **Kenwood TS-2000**.  
  
По умолчанию приёмник настроен на **3.6 МГц** (константа `RX_FREQ_HZ` в `RP2040_receiver.ino`).  
При смене частоты (константой или по CAT) системная шина `clk_sys` автоматически  
переподбирается под целый делитель гетеродина — ручная настройка тактов не нужна.

## ⚡ Основные возможности  
  
* **Прямая квадратурная оцифровка.** Два канала ADC (GPIO26=I, GPIO27=Q) в  
  round-robin на суммарной частоте `250 ksps` (`125 ksps` на канал).  
* **Квадратурный LO без джиттера с автоподбором шины.** Аппаратный PIO-делитель  
  `clk_sys` формирует гетеродин целым коэффициентом деления. На каждую частоту  
  приёма сканируется достижимая комбинация PLL, при которой `clk_sys/(4·D)`  
  ложится ближе всего к цели; шина при необходимости разгоняется (до 320 МГц).  
  См. раздел «Тактирование».  
* **Цифровой DDC.** Комплексный NCO-сдвиг ПЧ (`RX_IF_SHIFT_HZ = 3000 Гц`, сигнал  
  уходит от DC-пика и 1/f-шума ADC) добирает остаточную ошибку делителя; затем  
  CIC (R=2, N=3) и два каскада Half-band FIR → базовая полоса `15625 Гц` на канал.  
* **SSB-демодуляция.** Преобразование Гильберта (31-отводный FIR, Q15) даёт моно  
  USB или LSB. Доступны также режимы сырого I/Q и тестового тона.  
* **НЧ-фильтр звуковой полосы 3 кГц.** Симметричный FIR на базовой полосе  
  (целочисленная свёртка Q15) формирует ровную полосу 0…3 кГц с резким скатом выше.  
* **USB Audio-гаджет.** Полифазный интерполятор Фарроу (кубический, Q15) ресемплит  
  `15625 → 44100 Гц`, целочисленная АРУ нормирует уровень; поток PCM отдаётся через  
  TinyUSB Audio.  
* **CAT-управление.** Отдельный USB-CDC порт эмулирует Kenwood TS-2000: команды  
  `FA` (чтение/установка частоты, вызывает `rx_retune()`), `IF`, `ID`.  
* **Бортовой RTTY-декодер (опционально).** Пара согласованных фильтров (`rx_mf`)  
  на базовой полосе; включается флагом `RTTY_DECODE`.  
* **Телеметрия нагрузки.** Раз в секунду в основной Serial печатается загрузка  
  обоих ядер и счётчики дропов/клиппинга.

## Архитектура системы  
  
Проект задействует **оба ядра RP2040**; обмен — через lock-free SPSC-очереди  
с аппаратными барьерами памяти `__dmb()`.  
  
### Core 1 — реал-тайм DSP-тракт  
* Приём отсчётов от ADC+DMA (пинг-понг буфер), `250 ksps` (по 125 на канал).  
* Удаление постоянной составляющей (EMA DC-remove).  
* Комплексный NCO-сдвиг ПЧ (`RX_IF_SHIFT_HZ = 3000 Гц`) + компенсация остатка делителя.  
* CIC-децимация (`R=2`, `N=3`) и два каскада half-band FIR → `15.625 ksps`.  
* Преобразование Гильберта для SSB (USB/LSB) и НЧ-фильтр `0…3 кГц`.  
* Передача базовой полосы / демодулированного моно в межъядерную очередь.  
  
### Core 0 — вывод и периферия (Arduino)  
* Чтение потока из межъядерной очереди.  
* Ресемплер Фарроу (Q15) `15.625 → 44.1 кГц` и целочисленная АРУ.  
* Стриминг аудио `44.1 кГц` на ПК через TinyUSB Audio.  
* Разбор CAT-команд (`fldigi_cat_poll()`), опрос по таймеру раз в ~15 мс.  
* При `RTTY_DECODE=1` — согласованная фильтрация и декодирование RTTY.  
* Телеметрия нагрузки ядер и дропов раз в секунду.  
  
### Служебный аппаратный блок  
* Квадратурный LO через аппаратный PIO-делитель `clk_sys`.  
* Переключаемый блок полосовых фильтров (ДПФ) перед смесителем — код диапазона  
  выставляется на `subband_pins[0..3]` по таблице `SUBBAND_TABLE` (`vfo_hardware.cpp`).

## Тактирование и PLL  
  
1. Системная шина `clk_sys` работает на **129.333 МГц** (VCO `1164 МГц`, делители `3/3`).  
   При этой частоте делитель квадратурного LO для **3.6 МГц** выходит целым (`D = 9`),  
   что устраняет джиттер фронтов гетеродина.  
2. Периферийная шина `clk_peri` зафиксирована на `pll_usb` (**48 МГц**), поэтому ADC и  
   USB (TinyUSB) работают в паспортном режиме независимо от частоты вычислительных ядер.

## Сборка и прошивка  
  
### 1. Окружение  
1. Установите **Arduino IDE** (2.x или новее).  
2. Добавьте индекс плат в *Настройки → Дополнительные ссылки Менеджера плат*:  
   ```text  
   https://github.com/earlephilhower/arduino-pico/releases/download/global/package_rp2040_index.json  
   ```  
3. Установите платформу **Raspberry Pi Pico/RP2040 by Earle Philhower**.  
  
### 2. Параметры компиляции (меню Инструменты)  
* **Board:** `Raspberry Pi Pico`  
* **USB Stack:** `Adafruit TinyUSB` *(обязательно для USB Audio)*  
* **CPU Speed:** значение по умолчанию — карта тактов переназначается программно в `setup()`.  
  
### 3. Загрузка  
1. Откройте `RP2040_receiver.ino`.  
2. Переведите Pico в режим загрузчика (удерживая `BOOTSEL` при подключении USB).  
3. Нажмите **Upload**.  
4. Откройте Монитор порта на `115200` — пойдут строки телеметрии  
   `# CORE0_LOAD=.. CORE1_LOAD=.. aud_dropped=.. out_dropped=.. clip=..`.

## CAT-управление (FLDigi / Hamlib)  
  
CAT работает по **основному** `Serial` (один USB-CDC порт, общий с человекочитаемой  
диагностикой `# ...`). Отдельного/второго COM-порта нет.  
  
* Модель в FLDigi/Hamlib: **Kenwood TS-2000**, `115200 8N1`.  
* Поддержаны команды: `FA` (get/set частоты), `IF` (статус), `ID` (идентификация).  
  Команды оканчиваются на `;`.  
* set-`FA` (например `FA00003600000;`) вызывает перестройку приёмного тракта.  
* Опрос `fldigi_cat_poll()` вызывается из `loop()` по таймеру раз в ~15 мс  
  (обращения к TinyUSB-CDC дорогие, и для разбора CAT этой частоты достаточно).

## Спектральный вьюер (legacy)  
  
Скрипт `tools/rp2040_spectrum.py` рассчитан на текстовые FFT-кадры, которые эмитит  
**только** модуль `old/rx_spectrum.cpp`. В текущей основной прошивке этот вывод не  
собирается, поэтому вьюер «из коробки» данных не получит — нужно вернуть legacy-модуль  
спектра в сборку и включить его передачу.  
  
```bash  
pip install pyserial numpy matplotlib  
python3 tools/rp2040_spectrum.py /dev/ttyACM0  
```

## Настройка частоты приёма  
  
Рабочая частота задаётся в `RP2040_receiver.ino`:  
  
```cpp  
static constexpr uint32_t RX_FREQ_HZ = 3600000UL; // 3.6 MHz (80m band)  
```  
  
> [!WARNING]  
> При существенном изменении `RX_FREQ_HZ` убедитесь, что делитель квадратурного LO  
> относительно `clk_sys` остаётся целым. Дробный делитель вносит джиттер фронтов LO и  
> поднимает спуровый пол. При необходимости подберите частоту `clk_sys`/VCO так, чтобы  
> делитель снова стал целым.
